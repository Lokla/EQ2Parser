# Mirrored code

Each row is something that exists in both repos and is kept equal by hand. Nothing checks it. When
you touch one side, open the other and compare as the last column says. When you create a new
mirror, add a row here in the same change.

Parser paths are relative to the EQ2Parser root. `EQ2Lexicon/...` paths are in the sibling checkout.
This file says how to compare; it does not record whether the two sides agree today. Find that out
by reading them.

## Transport

| Signature header and algorithm | `src/EQ2Parser.Core/Upload/LexiconUploadClient.cs`: `SignatureHeader`, `Sign` | `EQ2Lexicon/backend/server/api/parses/ingest.py`: `PLUGIN_SIGNATURE_HEADER`, `_validate_payload_signature` | The two header strings are equal. Both sides: HMAC-SHA256, key = UTF-8 token, message = uncompressed body, lowercase hex. The pinned vector in `Hmac_Matches_The_Server_Vector` (`tests/EQ2Parser.Core.Tests/UploadClientTests.cs`) must equal what `_sign` in `EQ2Lexicon/tests/server/_parses_ingest_fixtures.py` returns for the same body and token. |
| Gzip and size limits | same file: `CompressUtf8Gzip`, `PostSignedAsync` | `EQ2Lexicon/backend/server/core/gzip_request.py`: `GzipRequestMiddleware`, `MAX_REQUEST_BODY_BYTES`, `MAX_DECOMPRESSED_BYTES` | The client sets `Content-Encoding: gzip` and signs before compressing; the middleware inflates before the handler reads the body. `EQ2Lexicon/tests/server/test_gzip_request.py` and `EQ2Lexicon/tests/server/test_parses_ingest_hmac.py` pin the server half. |
| Endpoint paths | string literals in `LexiconUploadClient`, `src/EQ2Parser.App/Services/RaidBossSyncService.cs` (`SyncAsync`), `src/EQ2Parser.App/Services/LexiconSyncService.cs` (`SyncAsync`) | route decorators in `EQ2Lexicon/backend/server/api/parses/ingest.py`, `EQ2Lexicon/backend/server/api/attendance.py`, `EQ2Lexicon/backend/server/api/auth_tokens.py`, `EQ2Lexicon/backend/server/api/zones.py`, `EQ2Lexicon/backend/server/api/act/pack.py` | List the six paths the client builds and find each decorator. | User-Agent | `LexiconUploadClient` constructor: `EQ2Parser/<version>`, version from `Directory.Build.props` | `EQ2Lexicon/backend/server/core/client_throttle.py`: `ClientThrottle.match`, `DEFAULT_CLIENT_LIMITS` | Read the configured prefixes and check whether any is a case-insensitive prefix of the parser's User-Agent. |
| Status codes and retry | `src/EQ2Parser.Core/Upload/UploadQueue.cs`: `SendWithRetryAsync` | every `HTTPException` raised on the path of `ingest_parse` | For each status the server can return, read which branch the queue takes: success, pause (401, or 403 without the reject header), fail this one upload (403 with the header), retry (0, 5xx, and 429 after its own wait) or drop. A new 403 that lacks the header pauses uploads for every user it reaches, and parsers up to v0.5.7 pause on any 403. |
| `Retry-After` on a 429 | `src/EQ2Parser.Core/Upload/LexiconUploadClient.cs`: `ReadRetryAfter`, `UploadResult.RetryAfter`; `src/EQ2Parser.Core/Upload/UploadQueue.cs`: `RateLimitWait`, `MinRetryAfter`, `MaxRetryAfter`, `RateLimitDelay` | `_client_flood_gate` in `EQ2Lexicon/backend/server/api/parses/ingest.py` (sends it, from `ThrottleVerdict.retry_after` in `EQ2Lexicon/backend/server/core/client_throttle.py`); `_rate_limit_handler` in `EQ2Lexicon/backend/server/app.py` and the `Limiter` in `EQ2Lexicon/backend/server/limiter.py` (the 60-a-minute limit, which does not) | Walk every 429 the ingest route can raise and note whether it carries the header and in which form. The client reads delta-seconds and HTTP-dates, holds the wait to 1 to 120 s, and falls back to 30 s without one. If the site turns `headers_enabled` on for the limiter, its 429 starts carrying the header and the fixed wait stops being the usual case: reread the comment on `ReadRetryAfter`. Tests: `tests/EQ2Parser.Core.Tests/UploadClientTests.cs`, `tests/EQ2Parser.Core.Tests/UploadQueueTests.cs`. |
| Reject header and the `server-not-allowed` code | `src/EQ2Parser.Core/Upload/LexiconUploadClient.cs`: `RejectHeader`, `RejectServerNotAllowed`; read by `SendWithRetryAsync` in `src/EQ2Parser.Core/Upload/UploadQueue.cs` | `EQ2Lexicon/backend/server/api/parses/ingest.py`: `REJECT_HEADER` and the allow-list 403 in `ingest_parse` that sends it; the tagged 403s in `EQ2Lexicon/backend/server/api/attendance.py` | The two header-name strings are equal. `RejectServerNotAllowed` equals the literal the allow-list 403 sends (the queue compares it ignoring case). No other code needs a parser constant: any non-empty value means "do not pause". Then walk every 403 the server can raise on these routes: each either carries the header (it is about this upload) or leaves it off on purpose (it is about the account). Tests: `tests/EQ2Parser.Core.Tests/UploadQueueTests.cs`, `tests/EQ2Parser.Core.Tests/UploadClientTests.cs`, `tests/EQ2Parser.App.Tests/UploadServiceRefusedServerTests.cs`, `EQ2Lexicon/tests/server/test_parses_ingest.py`, `EQ2Lexicon/tests/server/test_attendance.py`. |
| Default site host | `src/EQ2Parser.App/Services/AppSettings.cs`: default of `LexiconBaseUrl` | the site's public hostnames (`EQ2Lexicon/docs/architecture/server-registry.md`) | The default host must keep answering every path above. Released parsers cannot be re-pointed. |

| `swingtype` values | `src/EQ2Parser.Core/Combat/Swing.cs`: numeric values of `SwingCategory`; `PayloadBuilder.Build` emits one attack row per (ability, category) with that category's number, and `IsUploaded` keeps `StatusEffect` (30) local | `EQ2Lexicon/backend/server/parses/db.py`: `SwingType`, `_DAMAGE_SWING_TYPES`, `_HEAL_SWING_TYPES`, `_CURE_SWING_TYPES`, `_THREAT_SWING_TYPES` | Write both sets of integers side by side.
